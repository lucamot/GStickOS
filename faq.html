GStickOS is a lightweight distribution aiming at replacing the original Game Stick 4K Lite firmware. It uses RetroArch as frontend instead of the original UI.

To install GStickOS, download the latest image file from the website and flash it to an SD. Depending on your OS and your level of expertise there are different options to flash the image on an SD card — however, if you don't know how to start, try with Win32DiskImager. Be sure to have an SD card that is 2GB or more, and remember that all the data on the SD will be wiped when you flash the image (there's no turning back!)

There's a catch, however: if you have the original SD handy you can plug it in with a USB adapter and GStickOS will try loading it — you should then see it under /mnt/usb. Since there is only one USB port, having a USB hub is a strongly suggested option: you can connect a self-powered hub or even an unpowered one; given that you have a good power adapter, the game stick will power all your peripherals without problems.

You need ROMs for that. To load ROMs, plug a USB stick and it will be automatically mounted by the system — you'll find it navigating with the RetroArch file browser under /mnt/sdXY. You can simply plug a vFAT-formatted USB key and you should see every file you have inside there.

What to load on the USB key is outside the scope of this brief FAQ: you should look at the RetroArch documentation to know more about loading games, ROMs compatibility lists, etc.

Yes, sort of: if you plug a WiFi dongle, there's a popular driver built and loaded for it — RTL8188EU. If the WiFi dongle has this chip you're good to go.

To configure the SSID/password you have to put a wpa_supplicant.conf file in the root folder of a USB stick, plug it in, and then reboot after a few seconds. GStickOS looks for a wpa_supplicant.conf file in every USB device as soon as you plug it in; if it finds one, it will replace the internal configuration with the one provided. This is a sample wpa_supplicant.conf file — update as needed:

ctrl_interface=/var/run/wpa_supplicant
update_config=1
country=IT
network={
 ssid="my_1st_network"
 psk="MyPassword1"
}

network={
 ssid="my_2nd_network"
 psk="MyPassword1"
}

That's ok: grab yourself a program that is able to copy files over SCP (e.g. WinSCP) and use the root password above to transfer the files. My suggestion is to copy all the files under /mnt/extended, which is the largest partition on the SD. You can later see the files from the RetroArch UI by navigating again to /mnt/extended or wherever you put your files.

The extended partition (mounted under /mnt/extended/) is as big as the image you downloaded. If you put it on a large SD (e.g. > 2GB) you can resize the partition to take the full available space. It involves entering some commands on the terminal — there's no easy way yet:

  • SSH into the stick from a terminal (yes, in this weird world even Windows PowerShell can do SSH): ssh root@STICK_IP, replacing STICK_IP with the IP of the stick on your network. The password is gstickos.
  • Enter the command ps | grep retroarch and note the first column of the first two rows (two numbers, usually something in the 1000 range). Let's say you got 1262 and 1272.
  • Type kill -9 1262 1272 with the numbers from the step above. This will kill RetroArch (it's ok).
  • Type umount /mnt/extended.
  • Type resize2fs /dev/mmcblk0p5.
  • Wait — it might take long to finish. You can tell it did when a message starting with "The filesystem size is now" is shown.
  • Type reboot. The stick will reboot and you should have your whole SD available.

Fair enough — as long as you share your improvements with us :) Here are a few hints to get started:

  • Use Linux. A virtual machine with it is ok too. Don't use Windows — you'll regret it.
  • GStickOS is BusyBox based. This, among other things, means you have to be comfortable using the CLI.
  • The SD is not mounted without your intervention. Without being too technical, this is due to how they build the hardware of the stick and cannot be changed easily (you should flash a custom bootloader on an internal unlabelled chip — if you're into it, let me know).
  • The SD contains two partitions: a root fs and an extended partition. To mount them you have to specify an offset to the mount command; the offsets you need are 10MB and 138MB. Say you want to mount the extended partition — the command is: 
    sudo mount -o loop,offset=$((138 * 1024 * 1024)) /dev/sdX /media/sd
    Be sure to specify the correct path of the sd (i.e. replace /dev/sdX) and mount point (i.e. /media/sd).
  • Everything is built from scratch with a custom toolchain — from the base OS (BusyBox) to RetroArch and its cores. I made a docker image of the toolchain (here) with which you should be able to recompile everything, kernel included. A word of warning: using toolchains is the first step down the rabbit hole. My only clue here is that, after you load the docker image, you should source the env.sh file.
  • Most cores build without modification: this means that if you have your docker container running (and env.sh sourced) you should be able to just make them all. Some of them require small to big changes though — from updating some configurations to recompiling libraries and frameworks.
  • It's easy to be stuck with the toolchain, especially because it's based on an older GCC (4.9.2) and the equivalent glibc. Reach the Discord channel if you want to ask questions — I'm not always there, but I can try to answer your questions.
